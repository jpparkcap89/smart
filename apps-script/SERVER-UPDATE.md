# 순차 ID·신청자 수정·관리자 수정/삭제 적용

이번 변경은 브라우저 코드뿐 아니라 기존 Apps Script의 업데이트가 필요합니다. DB와 배포 주소는 그대로 사용합니다. 기존 접수 내역을 삭제하셨다는 전제로, **A열의 ID 자체를 `2026-001`부터 발급**합니다. 별도의 표시 접수번호는 만들지 않습니다.

## 1. 스크립트 파일 추가/갱신

기존 Apps Script 프로젝트에 아래 파일을 각각 붙여넣습니다. 같은 이름의 파일이 있으면 전체 내용을 교체하고, 중복 파일을 만들지 마세요.

- [Registration.gs](Registration.gs): 순차 ID·중복 전송 방지·공통 입력 검증
- [Participant.gs](Participant.gs): 성명·전화번호 끝 4자리 확인 후 본인 신청 수정
- [Admin.gs](Admin.gs): 행사 정보·접수 조회·수정·출석·취소·복원·영구 삭제

기존 `DB_ID`, `db_`, `settings_`, `clean_`, `literal_`, `output_`, `adminSummary_`, `doGet`은 유지합니다. 기존 `register_`는 남아 있어도 새 경로에서는 호출하지 않습니다. 실제 DB ID와 비밀번호를 GitHub나 채팅에 올리지 마세요.

## 2. 기존 doPost 함수 교체

기존 `doPost` 하나만 아래 내용으로 바꿉니다. 다른 파일에 같은 이름의 함수를 추가하지 마세요.

```javascript
function doPost(e) {
  try {
    const raw = e && e.parameter && e.parameter.payload;
    if (!raw || raw.length > 20000) throw new Error('올바르지 않은 요청입니다.');
    return output_(siteRequest_(JSON.parse(raw)));
  } catch (err) {
    return output_({ok: false, message: err.message || '처리 중 오류가 발생했습니다.'});
  }
}
```

## 3. 기존 배포 업데이트

**저장 → 배포 → 배포 관리 → 수정 → 새 버전 → 배포**를 선택합니다. **실행 사용자: 나 / 액세스 권한: 모든 사용자**를 유지합니다. 같은 배포를 업데이트하면 웹 앱 URL은 유지됩니다. `Settings.registrationEnabled`는 접수를 받을 때 `TRUE`로 둡니다.

서버 업데이트 전에는 브라우저가 이전 UUID 방식으로 새 신청을 저장하지 않도록 접수를 막고 ‘시스템 업데이트 중’으로 안내합니다. `getCapabilities`가 `idFormat: '2026-000'`을 반환하면 새 형식을 사용할 수 있습니다.

## ID와 DB 구조

- A열 ID가 `2026-001`, `2026-002` 순서로 저장됩니다. 1,000건 이후에는 `2026-1000`으로 이어집니다.
- 기존 B~R열 의미는 유지합니다. S열에는 ‘요청키’를 저장하며 중복 전송 확인용으로만 사용합니다. 사용자에게 보이는 또 다른 번호가 아닙니다.
- ID 카운터는 서버의 스크립트 속성에서 잠금으로 관리합니다. 취소하거나 영구 삭제한 ID를 다른 신청에 재사용하지 않습니다. 저장이 중단되면 번호에 빈자리가 생길 수 있습니다.
- S열에 다른 데이터가 있거나 UUID 형식의 기존 신청이 남아 있으면 임의로 덮어쓰지 않고 확인을 요청합니다. ID 카운터를 수동으로 초기화하지 마세요.

## 신청자 수정

‘신청 내용 수정’ 메뉴에서 성명과 전화번호 끝 4자리로 확인합니다. 동일한 확인 정보가 여러 건이면 임의의 신청을 반환하지 않고 운영 사무국으로 안내합니다. 성명별 실패 횟수를 제한하고, 본인 확인 후 15분짜리 서버 확인 토큰으로 해당 신청만 수정합니다. 토큰과 신청 내용은 URL이나 브라우저 저장소에 기록하지 않습니다. 페이지를 벗어나면 화면의 개인정보를 지웁니다.

수정 시 현재 동의 문구를 다시 확인하고, 변경 내용을 검토한 후 저장합니다. ID·접수시각·출석·접수 상태는 신청자가 바꿀 수 없습니다. 취소된 신청은 운영 사무국에 문의해야 합니다.

## 관리자 수정·삭제

기존 관리자 비밀번호로 인증합니다. 신청 정보 수정과 출석·취소/복원, 영구 삭제를 지원합니다. 삭제는 관리자 인증·정확한 ID·최신 수정 버전·명시적 확인이 있어야 하며 해당 행만 삭제합니다. 이미 삭제한 요청의 재전송으로 신청이 되살아나지 않도록 처리합니다. 행사 정보 편집과 비밀번호 비공개 원칙은 유지합니다.

```sh
python3 tests/registration-browser.py

```

위 검증은 가상 데이터와 모의 Sheets/API를 사용합니다. 실제 배포 후 확인할 때는 테스트 신청도 ID를 사용하며, 삭제해도 사용한 ID는 다시 발급하지 않습니다. 실제 참가자 정보로 테스트하지 마세요.
